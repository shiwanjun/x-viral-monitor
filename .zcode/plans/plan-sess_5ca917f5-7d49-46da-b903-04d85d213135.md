## 关注雷达：流速榜关系胶囊（GraphQL 主动扫描）

### 需求（已与用户确认）
在**流速榜每行右侧**新增关系胶囊，识别与该推文作者的关系：
- **互关**（TA 关注我 + 我关注 TA）· **我关注** · **关注我**
- **取关了**（之前有过关系、现在没有了，标红 + 时间）
- **无关系** → 显示该用户的**关注率 = 关注数 ÷ 粉丝数**（如 `3.2x`）
- 不做自动关注/自动取关；数据用 **GraphQL 主动扫描**（配合被动拦截）

### 架构与改动文件

**1. 新模块 `src/follow-radar/radar.js`（MAIN world 内容脚本）**
- **被动捕获**：`window.__xvmNet.onResponse(/graphql/…)` 解析所有 GraphQL 响应中的 user 对象（`core/legacy` 里的 `screen_name/name/following/followed_by/followers_count/friends_count`），零额外请求，实时更新关系缓存
- **主动扫描**：复用 starchart.js 的 `callGraphQL` 模式（`getTemplate` 捕获的 queryId + bearer/CSRF，`timelineEntries`/`bottomCursor` 分页），枚举 `Following`/`Followers` 全量列表；请求节奏 800–1200ms + 429 退避（`x-rate-limit-reset`）；断点续扫（存 cursor）
- **变化检测**：快照 diff（following/followers 集合 + 时间戳）→ 事件「TA 取关了我」「我取关了 TA」；被动侧同样做状态跃迁检测（f/b 从 true→false 即记录）
- **胶囊渲染**：hook 进 `renderLeaderboard()`（content.js:3187 行渲染处，`collectRanked()` 增加 `authorHandle` 字段），每行 `<li class="xvm-lb-item">` 末尾追加胶囊
- 取关语义说明：被动捕获下只有当 TA 再次出现在视野里（或深度扫描）才能发现变化，胶囊显示「曾经互关/关注，现已取关 + 发现时间」；深度扫描负责全量兜底

**2. 存储桥 `bridge.js`（ISOLATED world）**
- 新增 `XVM_FOLLOW_RADAR_GET/SET` postMessage 桥 → `chrome.storage.local`（参照现有 bookmark timeline 缓存模式，已验证该模式可用）
- Schema：`users{handle:{n,f,b,fc,fd,t,u,i}}`、`snap{following:{handle:ts},followers:{…},ts}`、`events[]`（上限 100）、`meta{lastScanAt,scanState,cursor}`

**3. 其余文件**
- `manifest.json`：content_scripts（MAIN world 块）追加 `src/follow-radar/radar.js`
- `styles.css`：`.xvm-fr-pill` 胶囊样式（互关绿/我关注蓝/关注我青/取关红/关注率灰）
- `_locales/en,zh_CN,ja`：互关/我关注/关注我/取关了/关注率/刷新关系/深度扫描等文案
- `tests/`：新增 radar 单元测试（状态判定矩阵、快照 diff、关注率计算、存储 schema）

### 交互
- 胶囊 hover → 小卡：@handle、关注数/粉丝数/关注率、关系历史（取关时间）
- 流速榜脚注：「刷新关系」（对当前榜单可见作者定向检查，≤20 人/批，500ms 间隔）+「深度扫描」（全量枚举，带进度条、可中断、断点续扫）
- 首次使用：被动捕获自动生效；主动扫描需先访问过一次 /following 或 /followers 页（用于捕获 queryId），否则给出提示

### 验证
- vitest 全量回归 + 新增测试；`npm run build:dist` 后本地加载验证胶囊各状态
- 版本号暂不变化（功能完成后再决定是否发 1.1）

### 阶段
- Phase 1：被动捕获 + 缓存 + 胶囊 5 态 + 存储桥 + i18n
- Phase 2：主动扫描（全量 + 定向刷新 + 进度/续扫/退避）
- Phase 3（后续可选）：用户主页互关标识徽章 + 弹窗统计页
